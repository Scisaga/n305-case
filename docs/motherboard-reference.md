## 模型用途

该模型为外壳设计提供统一的 PCB 基准、接口实体、安装孔、Z 向包络和散热接触关系。它不是主板厂商 CAD，也不用于生产或维修主板本身。

物理实体与避让体分开导出：

```text
主板物理参考
├── PCB + 四个安装孔
├── 04/06 接口实体 + 板载开关
└── 散热组件
    ├── 冷板 / 支撑
    ├── 风扇托板
    ├── 鼓风机壳与转子示意
    ├── 热桥
    └── 鳍片

独立避让参考
├── 散热组件包络
├── 底面器件包络
└── 四孔装配轴线
```

| 角位 | X / mm | Y / mm |

照片标定带来的孔位不确定度记为 ±0.35 mm。04/06 接口中心直接读取 [n305_panel_reference.py](../src/n305_panel_reference.py)，与已审阅的正投影图共用同一数据源。接口前沿现在受 103.4 mm 整体包络约束，位于 `X=±51.7 mm`，相对 PCB 只外伸 1.7 mm；旧 `X=±55 mm` 是错误的观察平面，已经撤销。

风扇外壳使用 [01 照片 PCB 对齐轮廓](../previews/calibration/01-blower-profile-trace.png)，当前包围范围约为 `X=-29.2…+25.4 mm、Y=-34.0…+19.8 mm`，保留朝 04 的出风蜗舌以及偏置进风口。叶轮改为 32 片后弯叶片，不再使用三根径向杆示意。机器转换记录见 [component-calibration.json](./component-calibration.json)。

01 顶视照片中可见的双孔长条不能用于确定 Z 高度；05 侧视照片也不支持它位于风扇上表面。旧模型中悬在风扇顶部的长条已删除，不再计入实体或避让包络。若以后需要还原该零件，必须先从侧视证据确定它与 PCB 的安装关系，不能再根据顶视遮挡关系猜高度。

## 散热组件不再悬空

模型显式建立以下连续路径：

```text
PCB → 冷板/支撑 → 风扇托板 → 热桥 → 鳍片
                       └──────→ 鼓风机壳
```

[接触链侧视图](../previews/reference/cooling-contact-path.png)用于视觉复核；构建脚本还会检查相邻件零距离且存在有效接触/交叠体积。数值结果见 [validation.json](../exports/reference/validation.json)。

这里的“接触”是壳体设计所需的拓扑和包络约束，不表示已经还原真实导热材料、螺钉、弹簧压力或内部热管截面。

## 精度分层

已测量或 PCB 对齐：PCB 外廓和厚度、总 Z 包络、四孔、接口中心、板载开关中心、风扇中心/进气口以及已确认的面板开孔尺寸。

照片重建或保守近似：PCB R4 圆角、连接器隐藏壳体的深度/局部外形、冷板支撑和热桥细节、风扇蜗壳折线间的曲率、叶片厚度/曲率、鳍片厚度/节距、底面器件块状避让体。双孔长条因缺少可靠的 Z 向证据而不建模。上述近似在源码和验证 JSON 中不得表述成用户实测值。

尤其要区分：面板孔的尺寸不等于板载接口实体的鼻端尺寸；未来外壳 CAD 应直接读取面板参数，并用接口实体/插头通道做覆盖校验。

## 本轮审阅重点

1. 四孔和 PCB 朝向是否正确。
2. 04 的 DC、HDMI 1、耳机、RJ45、双层 USB、HDMI 3 是否按 `+Y→-Y` 排列。
3. 06 两个 USB 是否水平，且各自 Z 中心差 0.10 mm；开关是否位于偏 07 一侧。
4. 散热器是否在 04 一侧，风扇中心和鳍片跨度是否符合照片。
5. 底面保守避让体是否需要进一步拆分或缩小。

确认这些内容后，才进入外壳开孔覆盖与装配面的三维阶段。
